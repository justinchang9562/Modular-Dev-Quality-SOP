# 事实来源与冲突处理政策

[返回主页](../README.md) · [企划书指南](01_Project_Plan_Guide.md) · [执行手册](02_Execution_Manual.md)

## 1. 按问题选择权威来源

事实来源（Source of Truth）必须与所回答的问题匹配。项目负责人决定需求与授权；官方资料说明外部组件的行为；实际改动与测试证据说明本次实现做到了什么。三者不能互相替代。

| 问题 | 应核对的来源 | 不能据此推导的结论 |
| --- | --- | --- |
| 系统要做什么、明确不做什么 | 负责人批准的当前企划书与变更记录 | 外部示例拥有某功能，不代表本项目也应实现 |
| 当前模块的顺序与边界 | 已批准执行手册、模块路线图与当前计划 | 下一模块容易实现，不代表可以提前开发 |
| 架构责任与依赖方向 | 已批准架构文档、相关 ADR | 既有代码违反架构，不代表该偏差已获批准 |
| 外部组件的约定行为 | 适用于所用版本和环境的最新官方说明 | 模型记忆或旧示例不构成官方保证 |
| 当前环境实际表现 | 可复现测试、运行记录、锁定依赖与配置 | 单次观察不能覆盖全部运行条件 |
| 当前模块是否完成 | 版本固定的改动、测试、审核和验收记录 | 状态文件写“完成”不等于已有验收证据 |
| 是否允许提交、发布或推进 | 负责人当前适用的明确授权 | 技术审核 PASS 不会自动产生操作权限 |

## 2. 外部技术事实的核验次序

1. **适用的官方资料。** 从最新官方入口定位当前模块相关的指南、完整使用案例、参考说明、错误与状态、限制、兼容性及迁移说明。
2. **版本对应的官方记录。** 生产环境仍使用旧版本时，核对该版本的官方说明及最新更正；同时检查新公告是否影响当前环境。不要把最新版行为直接套到旧版本。
3. **项目验证记录与 Skill。** 作为工程经验和复现入口，必须注明适用版本、来源、限制与验证方法。
4. **第三方示例与现有实现。** 可用于理解模式、发现问题和合法复用，不能覆盖官方契约。
5. **模型记忆与推测。** 只用于提出待验证假设，不能作为完成或通过的依据。

官方文档索引用来发现页面，合并摘要用来搜索和查漏；二者不能替代承载具体规则的官方页面。优先读取与模块有关的页面，不无必要加载完整站点或整个项目。

## 3. 先理解流程，再核对细节

读取顺序建议为：**官方指南与完整案例 → 精确参考说明 → 错误、限制与恢复规则**。记录实际核对的方法名称、签名、参数、必填项、字段、枚举、输入输出结构、错误及状态含义；官方标识保留原始拼写，解释另写，不自造“官方名称”。

页面上的流程图、时序图、状态图或架构图若影响行为，必须实际查看，并把请求顺序、状态转换、事件关系和失败处理纳入计划与测试设计。纯文字缺少图示不代表图示规则不存在。无法查看时如实记录缺失；若影响关键判断，先阻断该判断，不填写“已确认”。

同属官方资料也可能不一致。不要仅凭文件格式、页面日期或“示例能运行”决定谁正确；先检查适用版本、环境、说明范围和官方更正。

## 4. 来源清单模板

每个模块的计划与完成报告都记录实际读取的来源。未读过的页面不得列成已使用来源；不适用的分类注明原因。

```markdown
## Source Manifest — [模块编号] / [修订号]

| ID | 分类 | 标题与来源位置 | 版本 / 更新信息 | 访问日期 | 适用环境 | 确认的规则 | 对应验收 / 测试 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| S-01 | Guide / Example | [官方链接或受控文档路径与版本] | [原文标注；未标注则如实写明] | [YYYY-MM-DD] | [环境] | [具体规则] | [AC-01 / 测试位置] |

### Visual Review
- 页面与图示：[实际查看的位置；无相关图示时写 NOT APPLICABLE 并说明原因]
- 确认的行为：[顺序、状态或异常规则]
- 未解决差异：[无 / 待确认项编号]
```

文档的标注日期、访问日期与本地验证日期分开记录。需要保存快照时记录位置和内容摘要或校验值，并遵守来源的使用条件；不要把整份外部文档复制进 Skill。

没有外部组件的模块，可以将批准的业务规则、项目契约和相关决策作为主要依据，说明外部官方资料为何不适用，不能为填表编造来源。

## 5. 冲突处理流程

```text
发现差异
→ 写出两种说法、来源、版本与受影响行为
→ 检查版本、环境、适用范围和官方更正
→ 在安全且获准的环境内做最小验证
→ 可解释：记录依据，修订计划、代码或经验
→ 仍不可解释：标记待确认，阻断受影响决策，交负责人处理
```

实测与官方说明不符时，不把实测直接升级为普遍规则，也不忽略已观察的风险。保存最小复现、环境、预期与实际结果；必要时等待官方澄清。对无关且不受影响的工作可继续，但不能跨过受影响的验收门槛。

```markdown
## C-01 — [冲突标题]
- 来源 A / 版本：[位置与原意]
- 来源 B / 版本：[位置与原意]
- 受影响模块 / 行为：[范围]
- 最小复现与结果：[未执行则明确说明]
- 临时安全处理：[阻断或隔离办法]
- 状态：待确认 / 已解决
- 决策责任人：[负责人]
- 解决依据与后续修改：[确认后填写]
```

负责人可以调整需求或范围，但不能用批准意见把未确认的外部行为变成已确认事实。关键契约未解决时，保持 `CHANGES REQUIRED ⚠️`。

## 6. Skill 与开源复用治理

Skill 仅保存**已经实现、经过验证、来源明确、未来可复用且限制清楚**的工程经验。每条规则包含适用条件、依据、验证方法、版本或环境与最近验证信息。项目内部规则可引用批准的项目契约；外部行为仍须关联官方资料。

每次更新报告 `Added / Modified / Removed / Pending`。`Pending` 仅列在待确认清单，不能混入已验证规则。删除失效条目与新增条目同样重要；没有可复用经验时可明确写“无变更”。

| 复用级别 | 使用方式 | 必要记录 |
| --- | --- | --- |
| `DIRECT` | 在许可与兼容性允许时直接复用 | 来源、具体版本与文件、许可、署名、验证结果 |
| `ADAPT` | 小范围改造后复用 | 同上，并记录改造及其风险 |
| `PATTERN_ONLY` | 仅参考设计思路，不复制实现 | 参考位置、采用的模式、独立实现说明 |
| `DO_NOT_USE` | 存在权利、来源、安全或契约问题，禁止引入 | 拒绝理由和可选替代方案 |

没有明确许可的公开内容不自动获得复制权限。复用决定及其依据写入目标项目的复用矩阵；本方法库的许可也不替外部材料授予权利。

## 7. 何时重新核验

每个模块开始时核对相关官方入口和已知更正。依赖升级、环境变化、关键失败、资料冲突或审核后发生相关改动时，重新核对受影响来源与测试。将变化绑定到新版计划或审核包，不能拿旧版本的 PASS 覆盖新版本。
